# Conduit Project Guidance

- Conduit intentionally supports one connected Slack workspace. Treat single-workspace operation as a product boundary, not as a temporary limitation or a future multi-workspace roadmap gap.
- Priority sidebar membership is a starred conversation, or a group DM with a member whose 1:1 DM is starred (`starred_member`) that is also selected, unread or active within 4 hours. The derived flag is computed per render and never persisted or sent to Slack.
- Every text filter (pickers, member list, emoji picker, sidebar) matches through `search::SearchQuery` and `normalize_for_search`, so case and accents never matter (`a` matches `á`). Do not filter with `to_lowercase().contains`.
- Run `cargo fmt --check` and `cargo clippy --all-targets -- -D warnings` before every push. Enforce via `.git/hooks/pre-push`.

## Testing

- Graphical tests (anything that creates GTK widgets or windows, or needs a display) skip themselves unless `CONDUIT_GRAPHICAL_TESTS=1`. Plain `cargo test` never initialises GTK or opens a window. Never run them on a desktop session.
- Put every graphical test in a `mod graphical` and start its body with `run_gtk_test(...)` (`src/timeline/tests.rs`). The module path is what selects them, so a graphical test outside `graphical::` would run with the plain suite.
- The pre-push hook and CI run them under Xvfb. The filter selects exactly the graphical tests:

  ```sh
  xvfb-run -a env CONDUIT_GRAPHICAL_TESTS=1 GDK_BACKEND=x11 GSK_RENDERER=cairo GSETTINGS_BACKEND=memory GTK_A11Y=none cargo test graphical::
  ```

  With the variable set, a GTK that cannot initialise fails the test instead of skipping. Meson runs the same command as the "Graphical tests" target (`meson test --suite graphical`); "Cargo tests" runs everything else once, without a display.
- Wait on conditions with the shared `pump_until` (and `pump` for a fixed settle) from `src/timeline/tests.rs`, not ad-hoc loops or sleeps.

## Performance

Freezes come from work on the GTK main thread. These rules keep known hitches out; the `perf_guard_*` tests enforce them. The display-free guards run in plain `cargo test perf_guard` and meson "Cargo tests"; the GTK-backed guards (timeline rebinds) are graphical and run in the "Graphical tests" Xvfb target, so a full check needs both runs.

- Timeline re-renders rebind only rows a context change reaches (`MessageRenderContext::delta_from`) and keep rows whose message renders the same (`SlackMessage::renders_same`). Never put per-render values (tokens, scroll intent, image maps) into row-compared context. An arriving image rebinds only the rows that use it.
- Never probe image headers with gdk-pixbuf on the GTK thread for PNG, GIF, JPEG or WebP: `Pixbuf::file_info` is an out-of-process glycin call of tens of milliseconds. Use `image_header::declared_header`, and on the GTK thread `image_metadata::metadata`, which reads each file's header once (format, size, frames) instead of on every bind.
- Asset lookups on row binds do no repeated disk work: the cache root is canonicalized once, and a URL with no cached file (`resolve_cached_asset_path`, `resolve_custom_emoji_cached_file`) is remembered as a miss for a few seconds. A landed download ends it (`forget_asset_miss` on `ImageAssetLoaded`, `invalidate_or_set_custom_emoji_cached_file`).
- Animation players scale each frame once: they step the iterator by each frame's own delay (never the wall clock) and replay their first loop's textures, within `MAX_LOOP_CACHE_BYTES` over all players; past it they scale per frame. The loop's frame count comes from the worker (`image_header::loop_frame_count`).
- Row binds do not re-parse message text: it is parsed and converted to markup once (`text::cached_text_blocks`, an LRU keyed by text and dropped when a markup input `Arc` in the context changes). The hover quick bar is built once per change of recent reactions, custom emoji or mark-unread offer (`QuickBarCache`); hovering another row only retargets it.
- Sidebar rows rebuild only when something they draw changes: `SidebarRowModel::renders_same` ignores `latest_ts`, `avatar_url`, `search_aliases` and other ordering or lookup inputs, so the projection emits no `Update` for them (it still stores the new model). A recycled `ListItem` keeps its widget tree across unbind and rebind when `sidebar_bind_keeps_child` says the item draws the same. Custom status emoji textures are cached per URL and size (bounded) in `sidebar_widgets.rs`.
- The full sidebar render parses group DM member ids once per conversation (`group_member_ids`: a per-conversation cache revalidated against the raw member JSON, so the `ConversationCatalog::content_stamp` bump of an unrelated message reparses nothing; `SidebarBuildOptions::catalog_stamp` only opts into the cache, which is bounded), scores each row once and carries the score to the sort, computes participant coverage only for matched rows, and hands items to `SidebarProjection::reconcile` by value. Guards: `perf_guard_unchanged_catalog_parses_group_member_ids_once`, `perf_guard_search_keystroke_normalizes_each_row_field_once`.
- Image arrivals, failures and evictions only record their key and queue `UiInvalidations::IMAGES`; the frame flush handles the batch with one image-only render context that looks up just the arrived keys (`image_asset_context`, merged by `update_image_assets`), the `AvatarUserIndex` reverse map instead of a scan of every avatar, and one pass over the messages.
- Never wait on a launcher or an encoder on the GTK thread: open links, permalinks and files through `launch_external_uri` / `launch_external_file` (async `GtkUriLauncher` / `GtkFileLauncher`, not `open::that`), and PNG-encode pasted screenshots inside `gio::spawn_blocking`.
- Render the sidebar through `queue_ui_invalidations(UiInvalidations::SIDEBAR)` (one render per frame), not `render_conversations()`.
- Workspace patch handlers (`apply_workspace_patch`, `apply_workspace_timeline_projection`) update state and queue flags; the frame flush renders. Each socket event is its own patch, so the Threads list and Search/Saved (`MAIN`, queued only while that view shows) and unread separators with dwell-read rechecks (`MAIN_READ_MARKS`, `THREAD_READ_MARKS`, only for the visible channel or the open thread) never render per patch.
- Channel and thread message lists are shared `SharedMessages` (`Arc<Vec<Arc<SlackMessage>>>`): renders take `channel_messages_shared` / `current_thread_messages_shared`, never `.to_vec()`, and reloads store a merge only when it differs (`replace_if_changed`) instead of cloning the old list to compare. Unchanged messages reuse their existing `Arc` handles, and `build_store_items` uses zero-clone `TimelineMessageObject` sharing the same `Arc` identity to leverage `Arc::ptr_eq` fast paths in `same_row`.
- Shared `Arc` maps that render contexts and caches hold (user names, avatars, statuses, bots) change only through compare-first writes (`UserDirectoryState::project_users`, `remove_users`, `merge_user_names`): never `Arc::make_mut` one unless a value differs, since a held clone turns it into a full copy and breaks pointer-keyed caches. A users reset reports only added, removed or changed ids, and only those are projected.
- The conversation picker is a virtualized `GtkListView`: data changes queue `UiInvalidations::PICKER` (one rebuild per frame, only while a picker is open), a picker that is not mapped only marks itself stale (`PickerRefreshGate`), and picker sorts compute each row's sort key once. A data refresh applies keyed edits (`picker_edits`) and updates changed rows in place, so the scroll position and selection survive; only a new query resets to the top.
- People picker and `@`/`#`/`:` completion refreshes after data changes go through `PEOPLE_PICKER` and `COMPLETION` invalidations: nothing runs without an open picker or an active completion token, and an unchanged people list is not rebuilt. The people picker is a virtualized `GtkListView` (`PeoplePickerModel`) that splices only added, removed or renamed people and keeps checked people in a set, so checks and scroll position survive refreshes. Completion searches a cached `CompletionIndex` (fields normalized and sort keys computed once, rebuilt when the `StampedCell` stamps of users, groups, channels or custom emoji differ, so no change path can leave it stale); a query that extends the previous one filters the previous matches (`CompletionMatches`) instead of the whole index, and suggestion rows with an unchanged entry keep their widgets. Ranking changes must keep the index and the full-scan reference tests equal.
- Activity (`src/activity.rs`, `src/secondary_views/activity.rs`) rebuilds through `UiInvalidations::ACTIVITY` (one rebuild per frame) and only while its sidebar page is up; otherwise `activity_refresh` marks it stale and it rebuilds when shown. Rows are keyed, so unchanged rows keep their widgets (`kept_pairs`, `splices_around`). Unread state is derived per render, never persisted, and the backfill is one `search.messages` at most every 15 minutes. Nothing in Activity calls Slack at startup.
- Keep startup network fan-out bounded: history prefetch is capped at 12 conversations, run 3 at a time, and skipped when the cache is current. Bulk background store writes delay realtime messages through `store_batch_admission`.
- Startup and reconnect never fan out per item: user names come from one `users.list` (skipped while the persisted directory is under 6 h old). Channel discovery is a persisted, resumable sweep: stored channels hydrate at startup, a sweep runs at most every 24 h (starting 60 s after login or on first picker use, pages 4 s apart, capped per run, cursor persisted), and unknown `<#C...>` mention names are resolved on demand with at most 3 `conversations.info` calls at once (`DiscoveryGate`, `ChannelNameLookups`).
- Measure with `cargo run -- --debug` and the `scope="performance"` log lines before and after a change to these paths. Add a count-based `perf_guard_*` test for any new hot path.
