# Code Review Findings Remediation Plan

Source: full-codebase review performed 2026-09-08 at commit `18cc5db`, by 7 parallel review agents. File:line references are from that snapshot — re-verify before fixing, code may have moved.

## Phase 1: High-severity findings [checkpoint: 401f862]

- [x] Task: Fix screen-share fd double-close risk in huddles media pipeline (`huddles/media.rs:1214,1268,1297,1375-1386`) [1685b0a] — `attach_screen_share` hands a raw fd to pipewiresrc's "fd" property (int copy, no Rust-level ownership transfer), then the stored `OwnedFd` is closed again on detach/Drop. If pipewiresrc closes the fd internally on state teardown this is a double-close (EBADF or fd-reuse hazard). Confirm gstreamer-pipewire's actual fd-ownership contract for the "fd" property, then either call `into_raw()` so the element owns it exclusively, or `dup()` before handing it to the element so each side owns a distinct fd.
- [x] Task: Scope cache-corruption recovery to the single bad row in the store (`store.rs:764,3487-3499`) [d6ac727] — a single serde_json deserialize failure on one cached row currently triggers `query_or_reset`, wiping the entire workspace cache (all conversations/history/threads/users). Change corrupt-row handling to delete only that `(kind,item_key)` row; reserve full workspace reset for `validate_schema_v2` failure only.
- [x] Task: Stop rebuilding the whole thread catalog on every single event (`workspace_pipeline.rs:1934,1540,994,1088,2405,2383`) [2ffa5fd] — the full thread catalog is cloned into a HashMap, rebuilt, re-sorted, and persisted via `ThreadCatalogReplaced` on every single message/reaction/read event instead of being batched. Keep `ThreadCatalog` as a live mutable field on the coordinator, mutate in place, and persist only the delta.
- [x] Task: Avoid O(N² log N) writes when paginating channel history (`workspace_pipeline.rs:1498,426`) [6e48181] — `apply_timeline_snapshot` re-sorts and clones all channel messages and writes a full `HistoryReplaced`/`ThreadReplaced` payload on every paginated fetch page. Persist only the newly-accepted/removed messages per page; do a full replace only on the final page.
- [x] Task: Avoid full-vector clone+sort on every realtime patch in workspace state (`workspace_state.rs:1600-1660,1822,1848-1856`) [ec7a202] — `apply_timeline_changes`/`apply_projection_message_changes` clone the entire message vector into a fresh HashMap and run a full `sort_by`+`dedup_by` over the whole vector for a single incoming message/edit/reaction. Maintain a `ts -> index` map alongside the message vec for O(1)/O(log n) lookup/dedup; only clone changed entries; skip the sort when the new/updated timestamp is already in order.
- [x] Task: Guard `attention_metrics.rs` hardcoded enum-arm counts with a test (`attention_metrics.rs:8-10,331-357`) [2a99f57] — `ORIGIN_COUNT`/`DELIVERY_COUNT`/`PERSISTENCE_OUTCOME_COUNT` are hardcoded with nothing tying them to the actual enum arm count, unlike the sibling `AttentionReason::COUNT` which has a guard test. Add an exhaustive-match static assertion or a unit test mirroring the existing reason-code guard so adding an enum variant without updating the count fails loudly instead of panicking/corrupting indexing in prod.
- [x] Task: Use canonical timestamp comparison in thread catalog unread/reply logic (`thread_catalog.rs:261,270,298,420,469,483`) [1e11952] — several unread/reply comparisons use raw string `>`/`<=`/`<` on Slack timestamps instead of the canonical numeric-aware `slack_timestamp_is_after` (`models.rs:757`). Route all of these comparisons through `slack_timestamp_is_after` to avoid wrong unread classification on edge-case timestamp formats.
- [x] Task: Conductor - User Manual Verification 'High-severity findings' (Protocol in workflow.md) 401f862

## Phase 2: Medium-severity findings

- [x] Task: Scope custom URL schemes to validated call-block links only (`message_html.rs:4352-4356`) — `is_http_url`'s allowlist (`msteams`, `zoommtg`) is applied to all message-body links, not just call-block URLs, letting any user hand an arbitrary custom-URI string to the OS's registered protocol handler (both Teams and Zoom URI handlers have had real parsing CVEs). Restrict `msteams`/`zoommtg` acceptance to the call-block rendering path (sourced from a validated `call` block field); general message-body links should accept `http`/`https` only. (51b1e8e)
- [ ] Task: Validate payload signature on `download_media`, not just `download_preview_asset` (`slack.rs:1104-1110` vs `1047-1088`) — `download_media` trusts the server's `Content-Type` header alone for MIME typing while `download_preview_asset` additionally checks magic bytes via `is_valid_payload`. Apply the same signature check to `download_media` for a consistent trust model.
- [ ] Task: Pin an explicit redirect policy on the shared reqwest client (`http_client.rs`) — no explicit `redirect::Policy` is set; authenticated calls currently rely on reqwest's default cross-host header-stripping to avoid leaking `Authorization`/cookies on redirect. Set an explicit policy for defense-in-depth and confirm the pinned reqwest version still strips auth headers cross-host by default.
- [ ] Task: Batch same-channel message deltas in the store instead of reloading per message (`store.rs:2621,2674-2865`) — each `StoreChange::MessageDelta` independently reloads the full channel history (up to 200 messages) plus all threads for that channel, then rewrites both, per message. Batch same-channel deltas once per transaction, or route bulk/backfill paths through `HistoryReplaced`/`ThreadReplaced` instead.
- [ ] Task: Replace linear thread-catalog scans with direct HashMap lookups (`workspace_pipeline.rs:1694-1706,1339-1343,1676-1722,2103-2106`) — `apply_message`/`apply_reaction` and related code scan all threads in a channel to find prior replies despite the message already carrying `thread_root_ts()`, and duplicate work the HashMap-backed `ThreadCatalog` already does moments later. Replace with direct `(channel_id, thread_ts)` HashMap lookups.
- [ ] Task: Verify `page_complete` trust boundary for vanished-message eviction (`workspace_pipeline.rs:1479-1493`) — eviction of vanished messages only runs `if page_complete`, trusting the caller's flag fully; if a truncated or rate-limited fetch mis-sets `page_complete=true`, unrelated older history could be wrongly tombstoned. Confirm producer-side semantics guarantee this can't happen, or add a safeguard.
- [ ] Task: Confirm intended lane-preemption behavior in the sync scheduler (`sync_scheduler.rs:723-739`) — once the Maintenance lane is starved past its bound, it currently preempts even the Interactive (top-priority) lane, not just Foreground. Confirm this is intended; if not, restrict Maintenance to preempting Foreground only and give Interactive an untouchable fast path.
- [ ] Task: Add a reentrancy safeguard around the dense `RefCell` usage in `window.rs` — 249 `borrow_mut()` and 318 `borrow()` calls drive GTK signal handlers on the main thread with no reentrancy audit; a reentrant call path while a borrow is held panics the whole GUI via `BorrowMutError`. Add a targeted reentrancy test on the hottest paths (timeline patch application, composer toolbar refresh), or move the outermost signal boundaries to `try_borrow_mut` with a log-and-skip fallback.
- [ ] Task: Cap term count/length on the GNOME search-provider D-Bus interface (`gnome_search_provider.rs` `GetInitialResultSet`/`GetSubsearchResultSet`, ~136-158) — this D-Bus interface accepts calls from any session-bus peer with no cap on `terms: Vec<String>` count/length before scoring the whole catalog, allowing local CPU-DoS via oversized term arrays. Clamp term count/length before calling `search_prepared`.
- [ ] Task: Consider binding/signing the search-provider `ActivateResult` target (`gnome_search_provider.rs` ~166-175) — `decode_target` accepts any base64 JSON blob from any session-bus caller and fires `open-conversation` unsigned, letting any local app force navigation to a guessed workspace/channel. Low impact (UI-nav spoof only, no data leak) but worth binding/signing if this interface is meant to be trust-boundary-safe.
- [ ] Task: Fix membership-snapshot commit rejection on concurrent leave (`conversation_catalog.rs:83-87`) — `remove()` bumps `last_committed_snapshot` to its own revision, so `commit_membership_snapshot` rejects the entire in-flight snapshot (all channels) if a leave races a full refresh. Track removed IDs and exclude them from the incoming snapshot instead of invalidating the whole commit.
- [ ] Task: Stop `reply_count` from staying permanently inflated after a Slack-side deletion (`thread_catalog.rs:436`, also `248,420`) — `reply_count` only ever grows via `.max()`, even from authoritative "complete" payloads. Set it from the authoritative value when `complete == true` instead of only ever taking the max.
- [ ] Task: Strip control characters before logging URLs (`debug.rs:231-244`) — `url_for_log` strips credentials/query/fragment but not control characters, so a newline/CR in an attacker-supplied URL can forge fake log lines (log injection) since output goes to stderr as plain text. Strip or escape `\n`/`\r` before truncation.
- [ ] Task: Reorder empty-message vs. mutation-state checks in attention logic (`attention.rs:243` vs `250`) — the `EmptyMessage` check runs before `NonPostedMutation`, so a deleted/changed message with empty text gets mislabeled with reason `empty_message` even though the suppressed outcome is the same. Check mutation state first so metrics/logs report the correct reason.
- [ ] Task: Merge multi-workspace search results by score, not round-robin (`gnome_search_provider.rs:267-277`) — results from multiple workspaces are currently merged via round-robin `pop_front`, so a weak match from one workspace can outrank a stronger match from another. Merge into one Vec, sort by score once, then truncate.
- [ ] Task: Use `saturating_sub` consistently for progress-depth accounting (`runtime_mailbox.rs:491`, also `578,686,710`) — `progress_depth -= removed` uses raw subtraction while sibling counters use `saturating_add`, so one invariant slip panics (debug) or wraps to a huge value (release), permanently starving progress. Switch to `saturating_sub` for consistency.
- [ ] Task: Decide the fate of the dead `services/workspace_service.rs` module — the entire module (`WorkspaceSlack`/`WorkspaceService`) is `#[allow(dead_code)]`, fully tested, with zero real call sites, and will silently drift from actual `SlackApi` behavior over time. Per spec, do not delete without explicit user confirmation — flag this to the user and get a decision (wire it in, or delete it) before acting.
- [ ] Task: Cache normalized attention-preference terms instead of recomputing per check (`attention.rs:364-380`) — `normalized_terms` reallocates and renormalizes the whole name/keyword list on every match check, a hot path on pending-notification revalidation. Cache the normalized terms alongside the preferences and invalidate only when preferences change.
- [ ] Task: Move the blocking `send()` outside the metrics mutex (`attention_metrics.rs:200-235`) — `record_queue_send` holds a mutex across an arbitrary, potentially slow/blocking `send()` call, serializing all queue-metric recorders behind it. Send outside the lock.
- [ ] Task: Add tracing to the huddles subsystem's signaling/media fault paths — there is currently zero logging/tracing anywhere in `src/huddles/*`, so bootstrap/bridge failures, ICE failures, and pipeline Null transitions on error are all silent, hurting incident diagnosis. Add Info/Warn-level tracing; the existing redaction pattern on `SlackJoinSession`'s Debug impl (fields already `<redacted>`) shows the safe way to log around secrets, it just needs call sites.

## Phase 3: Low-severity findings

- [ ] Task: Replace hand-rolled secret zeroization with the `zeroize` crate (`huddles/signaling.rs:105-212`, `huddles/media.rs:98-124`) — the hand-rolled volatile-write zeroization on Drop duplicates a problem the audited `zeroize` crate already solves; swap it in.
- [ ] Task: Enforce the `TimelineDelta::new` revision invariant internally instead of at the call site (`window.rs:6875`) — `TimelineDelta::new(...).expect("timeline patches should form a delta")` only avoids `None` today because the caller does `revision.max(base_revision)` immediately before the call; a future edit to either function could silently reintroduce a panic path fed directly by Slack-sourced timeline patches. Make `TimelineDelta::new` take the max internally, or return `Result` and handle `None` explicitly in the caller.
- [ ] Task: Reduce blast radius of poisoned-lock panics in the runtime (`runtime.rs`, ~50 `expect("... lock poisoned")` call sites) — this many crash points means one background-task panic anywhere cascades into every subsequent lock touch panicking too. Consider `unwrap_or_else(PoisonError::into_inner)` on the hottest locks (state lock, user cache lock) so a transient panic in one task doesn't poison the whole runtime.
- [ ] Task: Saturate instead of panicking on sync-scheduler generation-counter overflow (`sync_scheduler.rs:679-683,771-775`) — `checked_add(1).expect(...)` panics on overflow (practically unreachable at u64 scale, but inconsistent with an otherwise all-`Result` module). Use `saturating_add` or document the invariant explicitly.
- [ ] Task: Index sync-scheduler admission scans if capacity ever scales up (`sync_scheduler.rs:667-668,674`) — two full linear scans over queued+running jobs per `admit()` call; fine today given bounded admission capacity, but should move to a HashMap index if capacity configs grow.
- [ ] Task: Verify size/hash of reused attachment cache files before treating them as complete (`slack.rs`, `download_attachment` cache-reuse path, ~1177-1186) — any existing non-empty file at the destination is currently treated as a complete, valid download without checking size/hash against the server's expected length. Store and verify expected size alongside the cache file.
- [ ] Task: Support the HTTP-date form of `Retry-After` (`slack.rs:2015-2023`) — `retry_after_seconds` only parses integer-seconds; a spec-compliant server using the HTTP-date form silently falls back to the 1s default. Add `httpdate` parsing as a fallback.
- [ ] Task: Log dropped invalid-UTF8 binary WebSocket frames (`socket_mode.rs:199-213`) — `Message::Binary(bytes)` with invalid UTF-8 is silently dropped with no log line, complicating diagnosis of unexpected binary frames. Log a debug line on the `Err` branch.
- [ ] Task: Delete the dead duplicate HTML rendering pipeline once confirmed unused (`message_html.rs`, ~600 lines of `#[allow(dead_code)]` functions: `blocks_html`, `block_action_html`, `external_control_html`, `rich_text_block_html`, `rich_text_element_html`, `rich_text_inline_children_html`, `rich_text_inline_html`, `block_text`, `legacy_attachment_html`, `linked_attachment_label_html`, `legacy_attachment_action_html`) — correctly escaped but unused, duplicates what `rich_message_normalize.rs`/`rich_components.rs` now do live. Per spec, confirm with the user before deleting.
- [ ] Task: Avoid cloning the whole thread catalog just to consume it (`activity.rs:115`) — `thread_catalog.clone().into_records()` clones the whole catalog unnecessarily; take `&self` or restructure ownership instead.
- [ ] Task: Don't abort the whole mention scan on one malformed `<@` token (`attention.rs:439-451`) — `contains_direct_mention` aborts the entire scan on the first malformed `<@` without a closing `>`, skipping valid mentions later in the text. Continue scanning past the malformed token instead of returning early.
- [ ] Task: Avoid full-buffer `Vec<char>` allocation on every composer keystroke (`composer.rs:698-763`) — `emoji_token_at_caret`/`mention_token_at_caret` collect the entire composer buffer into a `Vec<char>` on every keystroke/caret move with no length cap. Scan backward/forward from the caret directly over `&str` (byte-safe boundary walk) instead, or cache the char vec and invalidate only on buffer edit.
